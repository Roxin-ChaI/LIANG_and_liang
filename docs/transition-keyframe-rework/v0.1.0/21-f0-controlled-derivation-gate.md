# F0 controlled derivation gate — failed candidate, no F0 asset

The F0 specification was frozen before trying a single localized edit. Input
roles were explicit: KB2 was the edit target; B was only Feng face/suit
identity guidance, not the desired finger-to-chin pose. The request required
native 192×208 transparent hard-edge pixels and preservation of KB2's low
hands and narrow stance. Image editing was used only for this bounded
candidate; no accepted art was generated by a script or integrated into the
App.

The returned image is **1205×1305 RGBA** with intermediate alpha values,
not the required binary-alpha 192×208 pixel grid. More importantly, native
visual inspection and independent review found a whole character redraw:
different hair contour, face and glasses; newly rendered lapels, arms, hands,
trousers and shoes. Low arms/narrow legs resemble the requested *idea*, but
the pixels do not locally derive from KB2 and the face is not reliably the
approved Feng B face. The candidate is retained in a clearly named rejected
QA directory with SHA256
`43c6ff659e1d091967022f72537b6b934efb9c6e8209b25254662e7cc35baf4f`.
It is **not F0**. Nearest-neighbor downsampling would only shrink a redraw;
it cannot restore source provenance, character identity or the exact sole and
registration anchors. No 192×208 F0 PNG or KB2/F0 overlay was issued.

Technical gate: `F0_CANDIDATE_REJECTED`. Independent visual gate:
`VISUAL_FAIL`. Rejection is hash-bound; even a forged visual PASS cannot
override failed native geometry or alpha. A controlled local pixel artist's
derivation or another genuinely source-preserving method is needed; an extra
morphology bridge could be evaluated only *after* valid native F0 artwork
exists. Repeating whole-image generation or normalizing this candidate is not
a permitted repair. The F0→formal Feng Idle pose audit and full chain review
remain `NOT_TESTED`, so the need for a separate Feng entry animation is
`LIKELY_FROM_POSE_GAP` but **not confirmed against an actual F0**.

This gate does not modify A/K1/K2/K3/KB1/KB2/B, either formal atlas, the
player, Scheduler, Hooks, or the running App. It does not authorize full
animation fill or a v0.1.0 Tag.
