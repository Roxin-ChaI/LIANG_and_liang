# Idle 外观硬约束 — 2026-10-01

用户要求：**Idle 完全一致是不可放宽的条件。比例、像素画风及各项外观指标必须以 Idle 为准。**

唯一造型基准为正式 `assets/builds/gu/spritesheet.webp` 与 `assets/builds/feng/spritesheet.webp` 的 row 0 / frame 0；原始 `assets/gu/idle.png` / `assets/feng/idle.png` 用于理解人物细节。已证明正式帧与此前批准的 A/B 在 RGBA 像素上完全一致。失败生成稿、旧 K/F/E 派生链不得继续作为新造型的输入。

逻辑锚点不是 bbox 中点：Gu 全体 bbox 中心为 x=88，不能因此把角色整体搬到 x=96。原始像素的注册位置具有优先权。

既有“头部 68×80 / 49×54”是人工参考框尺寸，Gu 框涉及颈部/领口，Feng 下巴被手遮挡。它们不是精确头部分割，也不能作为候选中实际头部宽高的自动测量。新的报告明确区分参考框与实际 alpha 轮廓；保存全部 208 行的真实轮廓，禁止把传入的固定框原样返回后宣称头部尺寸通过。

## 必须一致的外观

- 同一人物的发型、发际线、眼镜形状与位置、五官画法、脸部轮廓及对应 Gu/Feng 气质。
- 正式 Idle 的头身比、肩颈衔接、肩宽、躯干、髋部、腿部体积、鞋型与服装剪裁。
- 原图像素颗粒、轮廓线、色块构造、明暗分区与配色。不能用任意“像素风”、低色数滤镜或高分辨率卡通缩小代替；Idle 本身的数千种源颜色要如实保留，不能擅自量化成另一种画风。
- 手臂与手、腿与鞋要有真实连续的解剖和动作轨迹；满足 bbox 不足以批准贴手、断袖、鼓胀肩膀或服装拼接。

Gu 与 Feng 是两个不同的批准形态。中间帧须在两者之间沿记录明确的轨迹变化，不能被解释成十帧都静止复制某个 Idle，也不能借“渐变”引入第三种人物设计。头部、肩部等语义部位需要实际图像标注及视觉核验，未知项保持 UNVERIFIED。

## 生成与验收流程

1. 先提交正式原生像素及整数 nearest-neighbor 放大参考给生成器，并携带 `contract.json` 中的全部约束；不继续引用失败人物稿。
2. 用原生 192×208 人物坐标制作/评估。Oversized 224×240 画布的对应 normal 区偏移为 (16,18)，不改变人物比例。特效与人物分开检查，不能拿能量外轮廓当身体 bbox。
3. 禁止对生成结果逐帧缩放、放宽身高或移动头部来隐藏不一致。生成器输出不符合硬指标时直接拒绝；提示词写了精确要求不代表实际执行成功。
4. 自动门禁先检查真实画布、身高、基线、Alpha、隐藏背景色和源配色；再进行真实脸部/发型/眼镜/服装/解剖的视觉门禁；最后逐段检查两端 Idle 和十帧动作的时间连续性。
5. 即使几何与配色全通过，也不自动批准素材。任何未知或失败都阻止标记完成、接入 App 或创建发布版本。
6. **只有 10 个变身动作帧。Gu Idle 与 Feng Idle 均在序列外，不计数，不复制进去凑帧。**
