# v0.1.0 core animation and schedule acceptance

Date: 2026-09-27 (Asia/Shanghai). This is a candidate QA report, not a
v0.1.0 release or tag. The official Codex App, project Hooks, Gu/Feng v2
atlases, and frozen transition images were not modified.

## Reproduced problem and repair

- **Reproduced:** a duplicate Running work-state message at renderer frame 2
  reset the visible playhead to frame 0 within 43 ms. The main process advanced
  `stateEpoch` for every work-state event, so the renderer reset `enteredAt`.
  The live red trace is at
  `standalone-app/evidence/v010-audit/duplicate-running.json`.
- **Fixed:** only a visible normal-state change restarts its playhead; identical
  work/form events no longer republish an unchanged visual state. The same live
  audit now returns PASS at
  `standalone-app/evidence/v010-fixed/duplicate-running.json`.
- **Transition robustness:** the main process now advances an oversized frame
  only after a matching Renderer paint acknowledgment, then its full 140 ms
  dwell. Stale operation/frame acknowledgments cannot advance a reversal.
  The 10 Gu→Feng and 8 Feng→Gu frames were each captured once from the real
  Electron window after paint. Work-state updates and a duplicate target during
  Gu→Feng left the current operation intact; completion restored Running.
- **QA-only race:** repeated same-frame render reports could overwrite a
  screenshot after the transition ended. Per-operation/frame capture keys
  prevent this. This was evidence tooling, not a frozen-asset defect.

## Beijing schedule

The rule remains Feng on Monday–Friday 09:00–12:00 and 14:00–18:00,
Gu otherwise. Tests cover exact boundaries, weekends, restart startup,
sleep/wake across nodes, forward clock jumps without historical replay, and
overlapping asynchronous reconciliations. The scheduler serializes delivery
and applies the latest fresh clock decision last. A one-minute, low-duty
clock check and macOS local clock-change notification supplement the precise
next-boundary timer and resume event; this does not change system time.

In the actual packaged App, injected-clock traversal of 09:00 → 12:00 →
14:00 → 18:00 triggered all four expected form changes through the renderer
and both full transitions, with no disk-atlas replacement or Settings Refresh.
Startup with 10:30 Beijing time restored Feng directly without replaying a
past transition. A **natural wall-clock transition** and an actual OS sleep or
manual system-clock change were **NOT_VERIFIED** on 2026-09-27; the next
natural boundary was the following Monday at 09:00.
