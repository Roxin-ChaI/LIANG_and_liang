# v0.1.0 animation audit (Commit 1)

Scope: project-owned standalone Electron App only. The official Codex App, approved
atlases, transition PNGs, and authorized Hooks were not changed.

## Live baseline

`tools/run_standalone_app_qa.py` launched the actual Electron renderer with a
temporary profile on 2026-09-27. It reported ordered renderer events for all 10
Gu→Feng and 8 Feng→Gu frames, plus Idle, Running, Hover, synthetic Drag, and
restart form recovery. Its transition assertion only proves that each frame
index reached the renderer; it does **not** prove that every frame was painted.
The physical mouse and real wall-clock boundary are not verified by this audit.

## Reproducible defect A1: duplicate work state resets Running

1. Start the independent App, enter Running and wait for renderer frame 2.
2. Send the same Running state again while the task is still active.
3. Renderer returns to Running frame 0 after 43 ms (audit trace at
   `standalone-app/evidence/v010-audit/duplicate-running.json`).

Cause: `standalone-app/main.mjs` increments `stateEpoch` for every `work-state`
event, even when the state is unchanged. The changed `playbackKey` causes
`standalone-app/renderer.mjs` to reset `enteredAt`. This is a timeline reset,
not a changed atlas frame or Hook defect. The live audit command intentionally
returns a nonzero exit status while the defect is present.

## Risks to verify during repair

- Transition frames are advanced by a main-process interval, while the renderer
  decodes and paints asynchronously. The existing renderer event is emitted
  before a confirmed paint; frame-index coverage alone is insufficient to rule
  out skipped visible frames under render delay.
- An interaction that changes `normalState` beneath a transition can reset the
  normal animation clock; transition priority itself is preserved by the
  player. Verify task-state restoration and repeat/reverse behavior live.
- The scheduler awaits `onTarget` before checking its generation. Two concurrent
  reconciliations can apply an older target out of order. A system clock change
  without a resume event does not currently force an immediate reconcile.

These are code-path risks, not claimed live visual failures. No source artwork
or atlas was altered to perform this audit.
